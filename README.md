# 一枚円（Ichi-Mai-En）

「積み上げるな、なぞれ」— 円形キャンバスに書いたメモが時間経過で自然に消えていくメモアプリ。
当初の個人向け円形メモの仕様に基づいて実装を開始し、その後アカウント連携・複数人での共有キャンバスへと拡張された。

> **⚠️ 現在テストモード**：消えるまでの期間の選択肢（`src/durationSelector.ts`）を、
> 動作確認をしやすくするため本来の値（今日中／3日／1週間）ではなく
> **1分／15分／30分** にしてある。実運用に戻す際は `CHOICES` の `label` と
> `lifespanDays` を今日中(1)／3日(3)／1週間(7) に戻すこと。
> なお「標準」（7日固定カーブ、`lifespanDays: null`）の選択肢はユーザー指示により
> UIから削除済み（後述）。`fade.ts` の `computeOpacity` 自体はnullを引き続き受け付けるので、
> 削除前に保存された既存データは変わらず7日カーブで消える。

## 画面構成

ヘッダーの3タブ（`src/main.ts`）で切り替える。

| タブ | 内容 |
|---|---|
| **キャンバス** | 個人用の円形メモ（本来の「一枚円」）。以下「実装した機能」節の対象 |
| **振り返り** | シークバーで過去の円の状態を辿る（後述） |
| **共有** | 鯖江メガネUI（SMUI）— 眼鏡フレーム形の1枚のキャンバスを、招待リンクで複数人が同時に編集する共有ボード |

ヘッダー右上のアカウントウィジェットはログイン状態を問わず常に表示され、ログインするとクラウド同期・「共有」タブが有効になる（後述）。

## 技術スタック

- TypeScript + Vite + Canvas API（UIフレームワークなし）
- 認証: Clerk（`@clerk/clerk-js`）— **任意**。未ログインでも「キャンバス」「振り返り」タブは従来どおりローカルのみで動作する
- クラウド同期・共有キャンバス用API: `https://api.onunu.me`（REST + WebSocket）— **ログイン時のみ**通信する
- 永続化: 個人メモは常に `localStorage`（キー `"memos"`）。ログイン時はサーバー側にも保存され、他端末とWebSocket通知で同期される。共有キャンバスは `localStorage` を使わずサーバーが唯一の保存先

未ログインかつ「キャンバス」「振り返り」タブのみを使う場合は、外部通信なし・`localStorage`のみで完結する（以前の設計のまま）。

## 使い方

```bash
npm install
npm run dev       # 開発サーバー
npm run build     # 型チェック + 本番ビルド（dist/ に静的ファイル出力）
npm run preview   # dist/ をローカルで確認
npm run test      # vitest（フェード計算・ヒット判定・ストアのユニットテスト）
```

`dist/` の中身はそのまま Vercel / Netlify / GitHub Pages 等の静的ホスティングに配置できる。

認証を有効にするには `.env.local` に `VITE_CLERK_PUBLISHABLE_KEY` を設定する（`src/clerkAccount.ts`）。未設定でもアプリ自体は起動し、「アカウント機能が未設定です」という警告バッジが出るだけで個人キャンバスは通常どおり使える。ただし「共有」タブ（SMUI）はログイン必須のため、鍵が無い環境では実質使えない。

## 主な機能（個人キャンバス／仕様の1〜7）

1. 円形キャンバス表示（パン・スクロールなし。円全体を常に表示することで「円の外に出られない」を満たす）
2. ドラッグでの手描き入力（円の外にはみ出さないようクランプ）
3. 経時フェード（0–24h:100% / 24h–3日:60% / 3日–7日:20% / 7日で消滅・`status:"faded"` に変更、物理削除はしない）
4. なぞって復活（クリック＆ドラッグでストロークに触れると即座に100%へ。確認ダイアログなし）
5. 消えるまでの期間の指定（今日中／3日／1週間 ※現在はテストモードで1分／15分／30分に変更中。上記の注記を参照。「標準」はユーザー指示によりUIから削除済み）
   - 「今日中」は選択後24時間固定（当日残り時間ではない）で消滅するよう実装（ユーザー確認済み）
   - いずれも標準カーブと同じ比率（1/7, 3/7）を指定日数（分単位のテスト値も小数の日数として同じ計算式に乗る）にスケールして適用
6. `createdAt` の記録
7. 振り返りビュー（シークバーで過去の円の状態を辿れる。検索・タグ・フィルタなし。なお当初あった「`status:"faded"` を作成日時順に一覧表示する」機能は、消えたものを後から検索できてしまいコンセプトに反するとの指摘を受け、第8弾で廃止した）

## 実装の変遷（個人キャンバス機能の追加履歴）

以下は個人キャンバス（「キャンバス」「振り返り」タブ）に対する変更を追加された順に記録した履歴。各弾の記述はその時点の状態であり、後の弾やSMUI（共有キャンバス）追加により上書きされた部分もある（例：第7弾で「タブを下部操作パネルに統合」としているが、共有タブ追加に伴い現在はヘッダーの3タブ構成に戻っている。現状は本README冒頭の「画面構成」を参照）。

### 第1〜2弾：道具バー

Appleメモ風の道具バーへ拡張（ユーザーからの追加依頼、意思決定込み）:

- **道具バー**：鉛筆／ペン／マーカー／消しゴムの4つを切り替えられる。太さ・質感が異なる（マーカーは半透明・乗算合成でハイライトのように重なる）
- **色**：ネイティブのカラーピッカー（`<input type="color">`）でフルカラーから選べる。既定値はこれまでどおりの墨色
- **消しゴム**：本当の手動削除。ドラッグで触れた部分だけをその場で消す（線が分断される場合は2本に分かれる）。「一枚円」は元々『手動削除できず、時間経過かなぞり復活でしか消えない』という設計思想だったが、ユーザーの明示的な指示によりこの原則を上書きしている
- **道具／色／期間の関係**：完全に独立した軸として実装。上段の道具バー（見た目・太さ・色）と、下段の期間セグメントコントロール（消えるまでの日数）はお互いに影響しない。道具の組み合わせごとに期間を固定する案もあったが、自由な組み合わせを優先した
- 全体リセット：確認（インライン、ネイティブdialogは使わず）を挟んでキャンバス上の全メモを削除

## 実装した追加機能（第3弾：紙質・パネル統合・振り返りタイムライン）

ユーザーからの追加依頼に基づく変更:

- **レポート用紙風の見た目**：キャンバス内側を白地にし、横罫線を薄く描画（`src/paper.ts`）。振り返りビューのプレビューにも同じ罫線を適用し、見た目を統一（当初は左端に縦のマージン線も入れていたが、赤みがかった色が目立ちすぎるとの指摘を受けて削除した）
- **操作パネルの統合**：道具バー／消えるまでの期間／全体リセットボタンが別々に並んでいた下部UIを、1枚の丸みを帯びたカードにまとめた。カード内は上段が道具バー、下段が期間セグメントと全体リセット（アイコンのみ）を横並びに配置し、境界線で区切る
- **振り返りビューのタイムラインスライダー**：「雨雲レーダー」のように、過去の任意の時刻へスライドしてその瞬間の円の状態（生きているメモも消えたメモも含む、なぞり直しの履歴も反映）を再現できる。スライダーの範囲は最も古いメモの作成時刻〜現在。プレビュー上部に選択中の日時をタイムスタンプとして表示
  - この機能のため、各メモは作成時刻となぞり直し（復活）のたびの時刻を配列 `traceHistory` として保持するように変更（`lastTracedAt` は後方互換のため引き続き保持）
  - 振り返りの一覧（消滅済みメモ）にも、それぞれの作成日時をスタンプ風の見た目で表示するようにした

### 座標系の変更（破壊的変更・重要）

上記の作業中に、円のサイズがウィンドウ幅に応じて動的に変わる仕様（前回追加）との組み合わせで、**メモの描画位置がウィンドウリサイズ後にずれる／歪む不具合**を発見したため、あわせて修正した。

- 修正前：ストロークの座標を「描いた瞬間の円の半径」を基準にした絶対ピクセル値で保存していたため、別のウィンドウサイズで開くと円のサイズに対して位置・大きさが合わなくなっていた
- 修正後：座標を円の半径を1とした正規化座標（-1〜1の範囲）で保存するように変更。どのウィンドウサイズで開いても、円に対する相対位置が常に一致する（`scripts/check-resize-stability.mjs` で、リサイズ前後で正規化座標が変化しないことを確認済み）

**注意**：この変更により、更新前の版で `localStorage` に保存された既存のメモは、座標の解釈が変わるため位置がおかしく表示される可能性がある。更新後に一度「すべて消す」で `localStorage` をクリアしてから使い始めることを推奨する。

## 実装した追加機能（第4弾：振り返りキャンバスの大型化とシークバーの配置）

- **振り返りのプレビュー円を通常キャンバスと同じ大きさに**：固定220pxだったプレビューを、通常キャンバスと全く同じ仕組み（`src/canvasSizing.ts` の `fitCanvasToContainer`、上限900px・下限200px）で動的にサイズ計算するよう変更。見た目の一致だけでなく、リサイズ時のロジックも一本化した
  - 振り返り画面には円の下に消滅済みメモの一覧も表示する必要があるため、円の取り分は「一覧の高さを引いた残り」（`flex:1; min-height:0`）として計算する。一覧が空・短い間はほぼ通常キャンバスと同じ大きさになり、一覧が伸びるとその分だけ円が縮む。それでも収まりきらない場合はページ全体がスクロールする
- **シークバーを道具バーの位置に**：振り返り表示中は、フッター操作パネルの上段（キャンバス表示中は道具バーがある場所）に、なぞり直し履歴を辿るシークバーを表示する。キャンバス表示に戻ると道具バーに切り替わる（同じ場所を共有し、常に片方だけを表示する）

## 実装した追加機能（第5弾：テキスト入力）

手書きだけでは書きづらい、という要望を受けて、道具バーに「テキスト」を追加した（`src/textLayout.ts` が中心）。

- **入力方法**：道具バーで「テキスト」（Tアイコン）を選び、円の中の書きたい場所をタップすると、その場に`<textarea>`が現れる。日本語のIME変換中のEnterと衝突しないよう、Enterでは確定せず、**フォーカスを外した時点（blur）で確定**する仕組みにした。何も入力せずに外した場合はメモを作らない。Escapeキーでその場で入力を取り消せる
- **文字サイズと下限**：テキスト選択時だけ、道具バーに文字サイズの3段階ステッパー（小/中/大、基準円=半径340pxで18px/24px/32px）が現れる。実際の描画サイズは通常のペン同様、円の半径に比例してスケールするが、**`MIN_FONT_PX`（12px）を下回っては描画しない**ようにしている（`textLayout.ts` の `fontPxForRender`）。ウィンドウを小さくしても、あるいは「小」を選んでいても、文字が読めなくなることはない
- **折り返しとリサイズ耐性**：入力確定時に一度だけ、基準円（半径340px・折り返し幅240px）で行分割した結果（`textLines`）をメモに保存する。フォントサイズも折り返し幅も同じ比率で実際の半径にスケールするため、ウィンドウをリサイズしても改行位置が変わらない（手描きストロークの正規化座標と同じ考え方）
- **なぞって復活・消しゴム**：テキストメモは折り返し後のテキストブロックを包む矩形（`boxWidth`/`boxHeight`、円の半径を1とする正規化単位）を持ち、なぞり判定・消しゴムの当たり判定に使う（`geometry.ts` の `circleIntersectsBox`）。手描きと違い部分的な編集はできないため、消しゴムで触れるとテキストメモごと削除する
- **経時フェード・振り返り**：色・消えるまでの期間・なぞり直し履歴・振り返りのタイムラインスライダーは手描きメモと完全に同じ仕組みを使う（`Memo` を `kind: "stroke" | "text"` の判別可能な union 型にし、描画だけ `src/memoRenderer.ts` の `renderMemoAt` に共通化した）
- **振り返り一覧のサムネイル**：56pxの丸いサムネイルには本文をそのまま縮小して置くと潰れるため、先頭1〜2行を数文字に切り詰めて中央表示するだけにしている（円からはみ出さないようクリップも行う）

## 実装した追加機能（第6弾：テキストの編集・「標準」の削除）

- **テキストの編集**：道具バーで「テキスト」を選んだ状態で既存のテキストメモをタップすると、なぞって復活ではなく編集用の`<textarea>`が開き、元の内容がそのまま入っている（カーソルは末尾）。フォントサイズ・色・消えるまでの期間は編集では変更しない（内容の書き換えであって見た目の再設定ではないため）。確定（blur）すると内容を上書きし、手描きメモを触った時と同様に「編集も触れたこと」としてなぞり復活と同じ処理（`lastTracedAt`更新・`traceHistory`への追加）を行う。**全文を削除して確定するとメモごと削除**される（`memoStore.ts` の `deleteMemo`）。Escapeキーでは、内容を書き換えていても元の内容のまま変更を破棄する
  - なお、テキスト以外の道具（鉛筆・ペン・マーカー）でテキストメモに触れた場合は、これまでどおり編集は開かず単純ななぞり復活のみが起こる。編集が開くのは「テキスト」道具でテキストメモに触れたときだけ
  - 実装上のポイント：新規作成時の「空のまま確定→何もしない」と、編集時の「空にして確定→削除」は意味が異なるため、Escapeでの取り消しを`cancelled`フラグで明示的に区別し、textareaの値を空にしてからblurさせる従来の実装とは分けた（値を空にしてから閉じると編集中のメモが誤って削除されてしまうため）
- **「標準」の削除**：消えるまでの期間の選択肢から「標準」（`lifespanDays: null`、7日固定カーブ）をUIから削除した（`src/durationSelector.ts`）。新しく書くメモは必ずいずれかの期間を明示的に持つようになる。ただし`fade.ts`の`computeOpacity`自体は後方互換のため引き続き`null`を受け付けており、削除前に保存された既存データは変わらず7日カーブで消える

## 実装した追加機能（第7弾：Escapeのバグ修正・移動機能・上部表示の整理と円の拡大）

- **バグ修正：日本語IME変換中のEscapeで入力全体が消える**：テキスト入力のEscapeでの取り消しは、キー入力の`keydown`を無条件に拾っていたため、日本語入力中に変換候補を1つだけ閉じたくてEscapeを押した場合にも「入力全体の取り消し」が発火し、せっかく打った文字ごと消えてしまう不具合があった。`KeyboardEvent.isComposing`（IME変換中かどうか）を見て、変換中のEscapeは無視するように修正した（`src/canvasView.ts` の `openTextEditor`）。変換中でない通常のEscapeでは、これまでどおり取り消せる
- **書いた・打った内容を移動できる機能**：道具バーに「移動」（十字矢印アイコン）を追加した。移動道具を選んで既存のメモ（手描き・テキストどちらも）を掴んでドラッグすると、そのままの形・内容で位置だけ動かせる。何もない場所をドラッグしても新規作成はしない（移動専用の道具として役割を絞った）
  - 手描きメモは全ストロークの全ての点を同じだけ平行移動する（`memoStore.ts` の `translateMemo`）。テキストメモは代表座標(x/y)だけを動かす
  - 円の外にはみ出さないよう、移動後の各点は円の半径1にクランプする（描画時のクランプと同じ考え方）。円周ぎりぎりまで動かすと、その部分の形がわずかに丸められる
  - 移動は「消えるまでの期間」やなぞって復活とは無関係な、位置だけの操作として扱う設計にした。`lastTracedAt`・`traceHistory`には触れない（移動そのものは内容に触れたことにはしない、という判断）。なお、移動道具でメモを掴む動作自体はテキスト道具での編集は開かない——テキストの編集は「テキスト道具でテキストメモに触れたとき」のみに絞ってあり、移動道具は編集とは独立している
  - 道具バー選択中はカーソルを掴む手の形（grab/grabbing）に変えて、動かせることを示している
- **上部表示の整理**：ページ上部にあった「一枚円」のタイトル見出しと、キャンバス／振り返りの切り替えタブを廃止し、切り替えタブは下部の操作パネルの一番上に統合した（`src/main.ts`・`src/style.css`）。ブラウザのタブタイトルはこれまでどおり保持している
- **円をさらに拡大**：見出しがなくなった分、上下の余白（`#app`のpadding・gap）も詰め、円の描画に使える縦方向のスペースを増やした。あわせて円の一辺の上限（`src/canvasSizing.ts` の `MAX_CANVAS_SIZE`）を900pxから1100pxに引き上げ、大きな画面ではこれまでよりはっきり円が大きく見えるようにした（下限200pxは変更なし。振り返りのプレビュー円も同じ定数を共有しているので、両方とも同じだけ大きくなる）

## 実装した追加機能（第8弾：操作パネルの余白調整・消えたメモの一覧廃止・シークバーの検索性低下）

- **下部の操作パネルをゆったりさせた**：以前は内容にぴったり合わせた小さめのカードで窮屈な印象だったため、横幅をもっと使う細長い「バー」に近い形（最大`min(640px, 94vw)`）に広げ、内側の余白・道具アイコン間の間隔・タッチ領域もひとまわり大きくした（`src/style.css` の `.control-panel` 一式）。見た目の情報量は変えず、単に呼吸できる余白を増やしている
- **振り返りビューから「消えたメモの一覧」を廃止**：円の下に消滅済みメモをサムネイル＋タイムスタンプで一覧表示していた機能を削除した。「なぞらなければ消えていく」というこのアプリのコンセプトに対して、消えたものを後から一覧・検索できてしまうのは矛盾する、というユーザー指摘による（`src/archiveView.ts` の `renderList`/`renderThumbnail` および関連CSSを削除）。振り返りビューで確認できるのは、シークバーで辿れる「その瞬間の円の状態」だけになった
- **シークバーの日時表示を相対時間にした**：シークバー上部のタイムスタンプを、絶対時刻（`2026/08/21 10:58:32`のような）ではなく「たった今」「23分前」「2時間前」「1日前」のような相対表現だけに変更した（`src/archiveView.ts` の `formatRelativeTime`）。狙いは検索性をあえて下げること——特定の瞬間をピンポイントで言い当てられないようにして、「記録を検索する道具」ではなく「なんとなく最近を振り返る道具」であり続けるようにしている
- **シークバーで遡れる範囲を最大3日前までに制限**：メモの実際の作成日時がどれだけ古くても、シークバーの下限は「現在時刻 − 3日」より前には遡れないようにクランプした（`src/archiveView.ts` の `MAX_LOOKBACK_MS`、`render()`内の`Math.max(oldestCreatedAt, now - MAX_LOOKBACK_MS)`）。これも検索性を下げるための制約で、標準の期間指定（今日中／3日／1週間）を将来また使うようになった場合でも、それより古い過去には振り返りようがなくなる

## 実装した追加機能（第9弾：操作パネルを1本の横並びの帯に統合）

- 第8弾までは「画面切り替え」「道具バー／シークバー」「消えるまでの期間＋全消去」がそれぞれ罫線で区切られた別々の段（縦積み）になっていたが、これを罫線なしの1本の横並びの帯にまとめた（`src/main.ts`・`src/style.css`）。すっきりさせたい、という明示的な指示による
  - 実装上は、画面切り替え・道具バー（シークバー）用スロット・期間セレクタ・全消去ボタンの4つを`.control-panel`の直接の子として横に並べ、`flex-wrap: wrap`で狭い画面では自然に複数段へ折り返すようにした。仕切り線ではなく余白（`column-gap`/`row-gap`）だけでグループを分けている——線を引くと、折り返した時にその線だけが浮いて見える問題があるため
  - 道具バー／シークバーのスロット（`#primary-slot`）だけ`flex: 1 1 240px`で余った幅を引き受けて伸びるようにしてある。シークバーはこれで実用的な長さのスライダーとして機能し、道具バー表示中はその余白の中でアイコン列が中央に収まる
  - 段が減って操作パネル自体の高さが低くなった分、円にまわせる縦方向のスペースがさらに増えている（第7弾で導入した`MAX_CANVAS_SIZE`の上限自体は1100pxのまま変えていないが、実際に到達しやすくなった）

## 共有キャンバス機能（鯖江メガネUI／SMUI）

「共有」タブは個人キャンバスとは別物で、複数人が同じキャンバスをリアルタイムに近い形で編集できる機能。ログイン必須（未ログインだとログイン誘導だけが表示される、`src/sharedRoomMenu.ts`）。

- **眼鏡フレーム形のキャンバス**（`src/frameShape.ts`・`src/smuiView.ts`）：左右レンズとブリッジが1枚につながった連続領域を1つのキャンバスとして描画する。個人キャンバスタブは常に円だが、共有キャンバスはフレーム形状として丸／楕円／長方形（角丸）から選べ、選んだ形状の輪郭がそのまま描画・なぞり・移動のクランプ境界になる
- **フレームの柄**（`src/framePattern.ts`）：マット／べっ甲／クリア／木目の4種類から選べる。形状は輪郭、柄は塗り（`strokeStyle`/`fillStyle`）という役割分担
- **見た目の設定**（`src/appearanceSelector.ts`）：フレーム形状と柄をまとめて選ぶポップアップ。共有キャンバスの下に埋め込み表示
- **ルームの作成・参加**（`src/sharedRoomMenu.ts`・`src/sharedCanvas.ts`）：「+ 新しい共有キャンバスを作る」でルームを作成し、招待リンク（URLの`?join=`パラメータ）を発行・コピーできる。リンクを開くと自動的にそのルームに参加し「共有」タブに切り替わる
- **同期方式**（`src/sharedCanvasSync.ts`・`src/realtimeSync.ts`）：変更はデバウンスしてサーバーへPUT。他メンバーの変更は、個人キャンバスと共用の1本のWebSocket接続でルーム単位に購読（`subscribe`）し、変更通知を受けたらすぐ取得し直すことでほぼ即時に反映する。通知の取りこぼしに備え、15秒間隔のポーリングGETも保険として並行して動く
- 道具バー・色・テンプレート配置・なぞり復活・消しゴム・移動など、描画に関する操作自体は個人キャンバスと同じ実装（`src/canvasView.ts`）を共有している

## テンプレート機能

何も書かれていない空のキャンバス（個人・共有どちらも）の中央には「ドラッグで書き始める」と「＋テンプレートを使用」の2つの選択肢が並ぶ（`src/canvasView.ts`のDOM製オーバーレイ、`.canvas-empty-state`）。後者を選ぶと画面全体のテンプレート選択（`src/templatePicker.ts`）が開き、あらかじめ用意した定型文をそのままキャンバスに配置できる（`src/templates.ts`）。項目は空欄のまま置かれるので、置いた後にテキスト道具でタップして書き込む。

## アカウント・クラウド同期

ログイン（Clerk）は必須ではないが、ログインすると以下が有効になる。

- **個人キャンバスのクラウド同期**（`src/cloudSync.ts`）：ログイン時に一度サーバーとローカルを同期し、以降はローカルの変更をデバウンスしてサーバーへ保存する
- **他端末とのリアルタイム反映**（`src/realtimeSync.ts`）：WebSocket（`wss://api.onunu.me/ws`）で「変更があった」という通知だけを受け取り、受け取るたびにサーバーから取得し直してローカルへ反映する。切断時は指数バックオフで再接続する
- **共有キャンバス（SMUI）タブの利用**：前述のとおりログイン必須

いずれも認証にはClerkのセッショントークンを使い（`src/apiClient.ts`）、未ログイン時はこれらの通信は一切発生しない。

## 実装メモ・意思決定

- メモは「道具」「色」「消えるまでの期間」をメモ単位で1つずつ持つ（ストローク単位ではない）。1つの連続したドラッグ操作、または短い間隔（1.4秒以内）で続けて書いたストロークは同じメモとして扱う。
  道具・色・期間のいずれかを切り替えると、書きかけのセッションは自動的に閉じ、次のストロークは新しいメモとして始まる（古いメモに違う設定のまま追記されるのを防ぐため）。
- 「なぞる」判定は、ドラッグ経路上の各点と既存メモのストローク（線分群）との距離がしきい値（12px）以内かどうかで行う。消しゴムが選ばれている間は、なぞり復活ではなく常に消去として扱う。
- 円の外周をキャンバス全体に収める設計にしたため、円外へのパンは仕組み上発生しない（「欲しい」機能のズームは未実装）。
- 円のサイズはウィンドウ幅・高さに応じて動的に決まる（`ResizeObserver`でキャンバスのコンテナサイズを常時監視し、幅と高さのうち小さい方いっぱいまで正方形として広げる）。下限200px・上限1100pxのみ設けている。

## 既知の制約

- Google Fonts（Klee One / Noto Sans JP）はオンライン環境でのみ読み込まれる。オフラインやフォント読み込み失敗時はシステムのsans-serifにフォールバックする（レイアウト・機能には影響しない）。
- 「共有」タブ（SMUI）はログイン必須。`.env.local`にClerkの鍵が未設定の環境では実質使えない。
- クラウド同期・共有キャンバスは外部API（`api.onunu.me`）への通信が前提のため、オフラインではログイン中でも同期は行われない（未ログイン時の個人キャンバスはオフラインでも従来どおり動作する）。
- 共有キャンバスの同期はWebSocket通知＋デバウンス送信によるほぼ即時反映だが、本格的な競合解決（同時編集時の差分マージ等）は行わず、最後に保存した内容が勝つ単純な方式。サーバー側に購読解除の仕組みが無いため、過去に見たルームの通知もソケット接続中は届き続ける（クライアント側で今表示中のルームかどうかを見て無視している）。
